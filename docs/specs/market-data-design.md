# 시세 데이터(market-data) 도메인 — Frontend 구현 현황 정리

## 배경 / 성격

`auth-design.md`/`user-design.md`/`property-design.md`와 같은 성격의 **요구사항 명세서 대비 실제 구현 대조 문서**입니다. 이 도메인은 국토부 API 호출·반경 확장·중앙값 계산 전부가 Backend 책임이라, Frontend가 실제로 관여하는 부분은 **Backend가 계산해서 내려준 결과를 얼마나 제대로 보여주는가** 하나뿐입니다. 그래서 이 문서는 다른 도메인 문서보다 "Backend 책임 / 범위 밖" 표시가 훨씬 많습니다.

**범위**: `MarketComparisonDto`를 소비하는 지점(`app/mappers/property.ts`, `app/(main)/properties/[id]/PropertyDetailClient.tsx`)만 다룹니다.

## 핵심 문제: DTO 자체가 요구사항이 구분하려는 상태를 못 담음

요구사항은 결과를 **성공 / 판정불가(3가지 사유) / 실패(4가지 사유)**로 세밀하게 구분하길 원하는데, 실제 FE가 받는 `MarketComparisonDto`는 이렇게 생겼습니다:

```ts
export type MarketComparisonDto = {
  status: 'UNAVAILABLE' | 'AVAILABLE';
  referencePrice: number | null;
  differenceRate: number | null;
  sampleCount: number | null;
  referenceDate: string | null;
};
```

`status`가 `AVAILABLE`/`UNAVAILABLE` **두 가지뿐**이라, "판정불가(표본부족)"와 "판정불가(주소정보 부족)"와 "실패(외부 API 장애)"와 "실패(호출 제한 초과)"가 전부 `UNAVAILABLE` 하나로 뭉쳐서 내려옵니다. FE 입장에서는 애초에 이 네 가지를 구분해서 보여줄 수 있는 데이터 자체가 없습니다. 아래 표의 "⚠️ DTO 한계"라고 적은 항목들은 전부 이 문제 하나에서 파생됩니다.

## 실거래가 조회 및 매물 가격 비교 — 요구사항 대비

| 요구사항 | 실제 구현 |
| --- | --- |
| 매물 등록/상세 조회 시 자동 트리거 | ✅ FE가 별도로 요청하지 않아도 `POST /properties`/`GET /properties/{id}` 응답에 `marketComparison`이 항상 같이 옴 |
| 매물유형별 국토부 API 분리 호출 / 반경 확장 / 면적오차 / 표본기준 / 중앙값 계산 / 조회기간 고정 | Backend 책임 — FE는 계산 로직에 전혀 관여하지 않고 결과만 받음 |
| 성공: 대표시세/가격차이/차이율/표본수/기준일/적용반경 제공 | ⚠️ **FE는 이 중 "차이율"만 화면에 씀.** `referencePrice`(대표시세), `sampleCount`(표본 수), `referenceDate`(기준일)는 DTO엔 있지만 매퍼(`mapPropertyDetailResponseDto`)가 아예 옮겨 담지 않아 화면까지 전달되지 않음. "적용 반경 단계"는 DTO에 필드 자체가 없어 Backend도 안 내려주는 것으로 보임 |
| 판정불가: "시세정보 없음" + 사유 제공 | ⚠️ DTO 한계 — `UNAVAILABLE`이면 사유 구분 없이 "아직 실거래가 비교 정보가 없어요. 국토부 실거래가 연동 예정입니다"라는 **고정 문구** 하나만 보여줌. 이 문구는 사실 "판정불가"보다는 "기능 자체가 아직 없다"는 뉘앙스에 가까워서, 실제로 정상 판정불가(표본부족)인 경우에도 오해를 줄 수 있음 |
| 실패: 외부 API 장애/타임아웃/호출제한/응답형식오류 각각의 사유 제공 | ❌ DTO 한계 — 4가지 실패 사유 중 무엇이었는지 FE가 구분할 방법이 없음. 판정불가와 실패조차 구분이 안 됨(둘 다 `UNAVAILABLE`) |

## 비기능 요구사항 — 대조

| 항목 | 요구사항 | 실제 |
| --- | --- | --- |
| 서로 다른 거래유형 직접 비교 금지 | O | Backend 책임, FE 범위 밖 |
| 비교 대상 주택유형·면적 기준을 결과에 표시 | O | ❌ **DTO에 이 정보가 없어서 표시 불가.** "몇 ㎡ 오차 범위 안에서 비교했는지" 같은 맥락이 화면 어디에도 없음 |
| 대표 시세 계산 방식(중앙값) 통일 | O | Backend 책임 |
| 표본 3건 미만이면 판정불가 처리 | O | Backend 책임 — FE는 그 결과를 `UNAVAILABLE`로만 받음(위 DTO 한계) |
| 반경 확장 로직을 정책값으로 관리 | O | Backend 책임 |
| **기준일·마지막 조회 시간 표시** | O | ❌ **`referenceDate`가 DTO에 있는데도 화면에 안 씀**(매퍼가 안 옮김). "마지막 조회 시간"이라는 개념 자체는 DTO에도 없음 |
| 주소/가격/거래유형 수정 시 기존 비교 결과 무효화 | O | Backend 책임 — 다만 Property 문서에서 이미 지적했듯 FE는 애초에 주소/거래유형 수정을 막아뒀고, 가격 수정은 되므로 그 갈래만 해당 |
| 오래된 시세를 최신처럼 표시 금지 | O | ⚠️ 기준일 자체를 안 보여주니 "오래됐다/최신이다"를 사용자가 판단할 근거가 화면에 없음 |
| 조회 기간 6개월 고정 | O | Backend 책임 |
| API 실패가 매물 등록/상세 조회 전체 실패로 안 이어짐 | O | ✅ 등록/상세 조회 자체는 `marketComparison.status`와 무관하게 항상 성공 — 시세 비교가 안 돼도 매물 정보 자체는 정상 표시됨(Property 문서의 "부분 성공" 항목과 일치) |
| 외부 API 필드 누락 시 안전 실패 처리 | O | Backend 책임 |
| 호출 제한 시 무제한 재시도 금지 / 반경 확장 최대 2회 | O | Backend 책임 |
| 짧은 시간 반복 조회 시 불필요한 외부 API 호출 축소 | O | Backend 책임(캐싱 등) — FE는 페이지 이동마다 새로 요청하며 자체 캐싱 없음 |
| 외부 API 응답시간/성공률/오류율 모니터링 | O | Backend 인프라 영역, FE 범위 밖 |
| 데이터 출처·기준일 표시 | O | ❌ 위와 동일 — 기준일 미표시. "국토교통부 실거래가"라는 출처 문구도 화면에 없음 |
| "정확한 시세를 보장하지 않는다" 안내 | O | ⚠️ 직접적인 안내 문구는 없음. 다만 매물 상세 화면 하단에 있는 일반적인 면책 문구("본 분석은 참고용 위험 신호이며...")가 위험신호 섹션에 있어, 시세 비교 섹션에는 해당 안내가 없음 |
| 반경 확장 시 사용자에게 안내("600m까지 확장해서 비교") | O | ❌ 적용 반경 정보 자체가 DTO에 없어 안내 불가 |
| 판정불가 사유를 이해할 수 있는 문구로 안내 | O | ❌ 위 DTO 한계 — 사유 구분이 안 되니 원인 설명도 불가능 |

## 요구사항에 없던 추가 구현

- `priceHistory`(월별 가격 추이 차트, `PropertyDetailClient`의 `LineChart`) — 실제 API 모드에서는 이 필드가 매퍼에서 아예 채워지지 않아 **항상 `undefined`이고, mock 모드에서만 나타나는 데모용 데이터**다. 요구사항엔 "추이 차트" 개념 자체가 없다 — 나중에 실제 기능으로 만들지, mock 전용으로 남겨둘지 확인 필요

## 남은 이슈 / 확인 필요 총정리

1. **`MarketComparisonDto`가 요구사항이 요구하는 상태 구분(성공/판정불가 3종/실패 4종)을 담을 수 없는 구조** — `status: 'AVAILABLE' | 'UNAVAILABLE'` 두 값뿐이라, Backend가 실제로 사유를 구분해서 계산하고 있더라도 FE로 전달할 방법이 없다. 이 도메인에서 가장 근본적인 이슈 — Backend 응답 스키마 확장이 선행되어야 FE 쪽 나머지 항목들도 의미가 생김
2. **`referencePrice`/`sampleCount`/`referenceDate`가 DTO엔 있는데 매퍼가 옮기지 않아 화면에 전혀 안 나옴** — 1번과 달리 이건 Backend 응답 확장 없이 지금 당장 FE만 고쳐도 되는 부분(매퍼 + `PropertyDetail` 타입 + 상세 화면에 필드 추가)
3. **데이터 출처·기준일 안내, 반경 확장 안내, 판정불가 사유 안내가 전부 없음** — 위 두 이슈가 해결되지 않는 한 사용성 비기능요구사항 대부분을 충족할 방법이 없음
4. **"정확한 시세를 보장하지 않는다"는 시세 비교 전용 면책 문구가 없음** — 지금 있는 면책 문구는 위험신호 섹션 것이라 시세 비교 섹션과는 무관
